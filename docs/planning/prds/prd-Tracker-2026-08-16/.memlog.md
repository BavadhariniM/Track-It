- (event) Extracted source docs (requirements.md v1, requirements-v2.md, docs/brief.md). v2 supersedes v1 (adds goal versioning, drops DST/timezone handling, hardens cheat-day/widget/import rules). brief.md (dated today, status ready) is canonical for MVP scope: single builder-first user, Android+iOS parity, no cloud sync/web/advanced recurrence/CSV export in v1.
- (decision) Stakes calibration: 'Personal now, maybe shared later' - lean PRD overall but with slightly more rigor on data integrity and UX polish than a pure hobby throwaway; built by/for the user themself, single-user for now.
- (decision) Core usage loop confirmed by user: open app -> log today's accomplishment/failure per eligible goal -> view rolled-up progress across day/week/month in the same daily view. Single recurring interaction, no multi-persona journey -> entry point set to Vision + Features (capability-first), not Journey-led.
- (decision) Vision confirmed as drafted: offline privacy-first single-user habit/goal tracker where calendar status is earned via precise rule-engine evaluation, not a flattened daily checkbox. Product's edge is correctness of edge-case handling, not technical novelty.
- (decision) Scope framing confirmed: single-user forever by design (not just 'for now') - no accounts, no sharing, no future-proofing for multi-user. Android and iOS must both work at initial release, not sequential/one-primary.
- (decision) Scope override: exotic custom recurrence ships in MVP now, not deferred post-MVP as v2/brief.md stated. Full set: every N days, every N weeks, every N months, specific day(s) of month, Nth weekday of month, custom date selections, biweekly, quarterly, rolling window (N-day), blackout/exclusion dates layered on any rule. Eligible-days axis is an arbitrary pick-any-weekdays selector, not limited to presets (workdays/weekends are just two convenience presets among many possible subsets).
- (decision) Goal rule semantics scope: MVP supports rich combinations only (frequency x eligible-days x target-comparison x tracking-type, freely combining per the use-case catalog). No cross-goal dependencies/if-then branching, no percentage targets, no streak-dependent targets, no time-of-day requirements, no duration tracking, no multiple-measurements-per-day in MVP. Matches v1 section 19's own 'future extensibility' framing and brief.md's stated exclusion (percentage/conditional/dependency rules) - engine should not architecturally preclude adding these later, but none ship now.
- (decision) Confirmed: use-case catalog (axes: tracking type, target comparison, evaluation period, eligible-days rule) plus worked examples table is the right structure for documenting supported scheduling/target patterns in the PRD. Eligible-days confirmed as arbitrary subset selection (e.g. Mon/Tue/Thu/Sat), not limited to workday/weekend presets.
- (decision) Daily logging & evaluation confirmed as synthesized from v2 (entry, corrections floor at 0, cheat-day quota default 0 doesn't reduce Exact targets, DNF superseded by period outcome, day-level red only on mathematically certain failure). New rule for rolling-window goals (e.g. 10x/any 14 days): a day turns red once the remaining days in the trailing window can no longer mathematically reach target - same certain-failure logic as weekly/monthly, applied to a sliding window instead of a calendar period.
- (decision) Calendar/dashboard/stats confirmed as synthesized from v1+v2 (month/week/day views, configurable week-start default Monday, dashboard rollups, goal detail screen, rule-aware streaks based on successful periods not consecutive days). Rolling-window goals have no streak stat (N/A) - they show current pace/status only, since there's no fixed period boundary to anchor a streak counter to.
- (decision) Notifications & widgets confirmed: single global reminder time applied across all goals (no per-goal custom times in MVP). Widgets: home-screen only (no lock-screen), exactly 3 types per v2 (Today/Week/Month), rendering precomputed cached status only, never live evaluation. v1's small/medium/large widget-size breakdown superseded by v2's 3-type scope.
- (decision) Data management confirmed: JSON export/import (goals, logs, cheat days, settings, categories, notification config, metadata), import validation rejects malformed/mismatched/duplicate/orphaned/invalid data and always prompts user on conflict (never silent). Delete=Archive stands (no hard delete of individual goals), BUT a separate 'reset app / erase all data' nuclear option is required as an escape hatch for starting completely clean. Import merges into existing local data (not a full-replace/restore-only operation) - this is why duplicate-ID conflict handling matters.
- (decision) NFRs confirmed: absolute offline-first (no login/account/server ever), no timezone/DST handling, single-device only (manual export/import merge to move data), Android+iOS parity at initial release, rule-engine correctness treated as core quality bar, data durability guarantee (only in-flight unsaved entries at risk). Zero telemetry/analytics/crash-reporting - no third-party network calls at all, not even opt-in anonymous crash reporting.
- (decision) Success metrics and MVP scope boundary confirmed as drafted, no changes requested. Moving to full PRD draft assembly.

- (decision) Finalize triage resolved 4 phase-blocking decisions: (1) every-N-days/weeks recurrence anchors to the goal's chosen start date, fixed grid, no re-anchoring on edit. (2) Cheat Day quota resets per evaluation period (not a flat lifetime cap), configurable per goal, default still 0. (3) No timestamped multi-entry-per-day as brief.md described; instead Counter goals allow repeated increments throughout the day summed into one daily total with no per-increment timestamp - deliberate simplification vs brief.md's explicit timestamped-multi-entry commitment. (4) Blackout Dates exempt a day like a forced Cheat Day (no failure that day) without shrinking the eligible-day pool/denominator - target count stays anchored to the original eligible total.
